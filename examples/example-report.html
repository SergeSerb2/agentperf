Biggest wins: likely causes and fixes

1. Antivirus / endpoint security scanning likely

up to +254 AgentMark
if the affected tests reached reference speed (upper bound; gains overlap and do not add up)

Security scanning taxes every process start and small-file operation. This is the single largest software effect agentperf sees on Windows: the same PC scored 67 natively and 1000 in WSL2.

Evidence

  • Probe: real-time antivirus scanning is active.
  • Probe: endpoint security agent detected (endpoint security agent (name withheld)).
  • Pattern: a shell start costs 62.4 ms here vs 1.1 ms on the reference, while raw compute stays competitive. Scanners inspect every process start and file write; pure CPU work does not pass through them.

Fix

  • Exclude your code folders, package caches (npm, pip, cargo), and ~/.agentperf from real-time scanning.
  • On Windows, put code on a Dev Drive (ReFS) so Defender uses performance mode, or run agents in WSL2 with repos on the Linux filesystem.
  • On a managed machine, ask IT for a developer-folder exclusion instead of disabling protection.

Affected tests: files.create, files.delete, files.edit, files.read, files.stat_walk, process.exec, process.node, process.parallel, process.python, process.shell

2. Windows power plan observed

up to +94.0 AgentMark
if the affected tests reached reference speed (upper bound; gains overlap and do not add up)

The active plan is 'Balanced'. Balanced and saver plans add latency to short bursts and I/O.

Evidence

  • Probe: powercfg reports 'Balanced'.

Fix

  • Switch to High performance or Ultimate Performance for agent work.

Affected tests: process.exec, process.node, process.parallel, process.python, process.shell

3. Older Python interpreter possible

up to +0.825 AgentMark
if the affected tests reached reference speed (upper bound; gains overlap and do not add up)

The pure-Python test trails and this machine runs Python 3.11.9 vs 3.14.4 on the reference. CPython 3.11+ is much faster at interpreter loops. Only one low-weight test depends on it.

Evidence

  • Probe: python 3.11.9 here, 3.14.4 on the reference.
  • Pattern: compute.python ratio 0.38; C-backed compute tests are less affected.

Fix

  • Use Python 3.11 or newer for agent tooling and scripts.

Affected tests: compute.python

4. PowerShell start cost on Windows observed

PowerShell starts in 638 ms vs 62 ms for Git Bash. Harnesses that run commands through PowerShell pay this per command.

Evidence

  • Measurement: diag.powershell 638 ms; process.shell 62 ms.

Fix

  • Prefer WSL2 or Git Bash execution for agents where the harness allows it.
  • Trim the PowerShell profile; the no-profile number is the floor.

Affected tests: not scored (paid per tool call)
